# Word 批注交付

Word 输入的主交付为 `<document-slug>-reviewed.docx`，其中 document-slug 为英文文档简称，输出路径通过参数指定。使用真实 Word 批注，新增批注的作者必须逐字为 **概要设计检查助手**。保留源文件，保留副本中的正文、段落/表格格式、图像、目录、页眉页脚、域、已有批注和修订。不得用正文中的括号文字、修改痕迹或独立问题清单代替批注。

## 从证据定位到批注

- 先读取原稿并建立段落索引，表格单元格段落与图示所在段落均包括在内。段落序号只对这份原稿有效，必须连同原稿 SHA-256 使用；段落号不是 Word 页码。图片仍需实际查看，工具索引不识别图片语义。
- 把批注锚定到直接承载问题的段落、表格单元格或图示。优先选具体文本所在段落；跨章节冲突在主要位置批注，并在批注正文中写清另一处证据的章节、表号或图号及原文。需在多处提醒时使用同一发现编号说明关联，避免重复计数。
- 缺项没有可选原文时，挂到应承载该设计的章节标题或现有相关说明，并注明缺失范围、判断依据和需补充内容。图内文字不直接改写，在图所在段落或图题挂批注，写明图中节点/连线。无法可靠定位的发现先核实，不随意挂到文档开头。
- 批注头用中文表达严重程度、问题类型和确认状态，保留发现编号。正文优先用“问题、建议”两段：问题用1—2句说清哪里不一致、什么情况下有影响，并带必要的对照位置；建议只列该问题的关键修改或确认事项。证据和影响可合入问题，不必单独铺开四段。缺证保持“待确认”，推断保持“需核实”，不能为缩短文字删掉判断边界。
- 最终回复给出 Word 副本链接，简述发现的问题数和待确认项数与未审范围。范围、例外和限制可在回复中说明；除非用户要求，不另造一份长报告。
- 没有问题时仍交付源稿副本，在回复中说明“本次范围内未发现问题，新增批注0条”，不制造问题批注。

## 中文批注与简明写法

推荐形式（编号由工具自动加在前面）：

```text
[F21]【高｜待补充｜待确认】Nacos跨中心部署方式不清
问题：正文说两中心共用一个集群，图中却分别画了一个。断开连接后，各中心如何继续运行还未说明。
建议：确认是一个跨中心集群还是两个独立集群，统一图文，并补充断链时的注册、配置更新和恢复方式。
```

| 内部字段 | Word中的中文写法 |
|---|---|
| critical / high / medium / low | 严重 / 高 / 中 / 低 |
| conflict / omission / risk / drift / evidence_gap | 内容冲突 / 内容缺失 / 潜在风险 / 落实偏差 / 待补充 |
| confirmed / suspected / insufficient | 已确认 / 需核实 / 待确认 |

- 英文枚举只保留在内部底稿及JSON契约，不作为用户批注标题。严重程度与确认状态分开，不能把“高”理解为已确认发生事故。
- 一条批注只讲一个问题，通常100—180个中文字；复杂冲突可稍长，以读者能理解和采取行动为准，不机械凑字数或截断。
- 少用“闭合、故障域、隔离令牌”等抽象术语；确需使用时说明实际含义。对已有技术名称可保留API、Nacos等，不要求把产品名翻译成中文。
- 跨章节只保留能支持判断的关键差异和位置；完整证据、计算及评审过程留在内部底稿。关联位置复用编号，用一两句话指向主批注。
- 不把“文档没说明”改成“系统没有”，不把“可能”改成“一定”；未提供的专题可列为待确认，不能仅因清单有此项就报缺项。

## 内置工具

`scripts/word_comments.py` 使用 Python 3 标准库，直接增量修改 DOCX 包内批注和必要关联，保留无关部件原始字节。工具按整个目标段落锚定，不拆分文字 run，适合正文、表格和图所在段落。需要更精细的批注范围时，可使用宿主已有的 Word 或 OOXML 工具处理，并执行同等保真和锚点校验。

```text
python -X utf8 scripts/word_comments.py index source.docx --output paragraph-index.json
python -X utf8 scripts/word_comments.py apply source.docx comment-plan.json --output source-reviewed.docx
python -X utf8 scripts/word_comments.py verify source.docx comment-plan.json source-reviewed.docx
```

计划为 UTF-8 JSON。`source_sha256` 从索引复制；`paragraph` 为索引中的从1开始的段落序号；`quote` 为该段连续原文，用于确认位置，重复原文依靠段落号和文件散列消歧。图片无文本时可使用空 quote，工具仅允许在含图或对象的段落这样定位，仍需人工看图判断。

```json
{
  "source_sha256": "从索引复制的64个十六进制字符组成的SHA-256散列值",
  "annotations": [
    {
      "finding_id": "F01",
      "paragraph": 12,
      "quote": "同步调用超时设为五秒",
      "text": "【高｜内容冲突｜已确认】超时设置不一致\n问题：本段接口等待5秒，第3.2节下游处理允许8秒，正常交易也可能被提前中断。\n建议：统一上下游超时和重试设置，并说明超时后如何查询最终结果。"
    }
  ]
}
```

工具自动在批注正文加发现编号，作者不可通过计划覆盖；多位置批注可复用发现编号。任何散列不符、引用不符、段落越界均整体报错，不跳过失败项生成“成功”的半成品。annotations 为空数组时，工具生成与原稿逐字节相同的副本。输出文件必须是新路径，禁止覆盖原稿或已有交付。

## 交付校验与格式限制

1. 检查每项计划都对应一个新增批注，作者、内容、段落锚点匹配，ID不与已有批注碰撞，批注部件/关联/内容类型齐全。保留已有批注作者和内容；不改写已有批注的作者。
2. 核对源文件未变化，除新增批注及必要关联外，正文与其他部件保持不变。工具 apply 会自动 verify；外部工具处理也必须验证。检查页数、表格、图、目录和修订的保真；可用时在 Word 打开或渲染检查。渲染图未显示批注不能作为批注不存在的证据，仍需结构校验。
3. 内置工具支持普通 Transitional DOCX 的主文档（含表格、图和文本框段落）。页眉页脚、脚注等主文档以外的部件的批注请用支持该位置的工具并独立核对；不默默移到正文。含数字签名、受编辑保护、加密、Strict OOXML 或损坏的文件不能直接处理，明确限制后采用用户认可的可编辑副本。
4. 旧 `.doc` 先经可用的 Word 转换为 `.docx`，保留原 `.doc`，核对转换前后布局和内容后再批注；不能只改扩展名。没有转换能力时，说明需要可编辑的 DOCX 文件，不宣称已交付批注版。没有 Word 原稿时可审其他材料，但需明确尚未生成 Word 批注交付。

OOXML 依据：Microsoft Learn，`https://learn.microsoft.com/en-us/office/open-xml/word/how-to-insert-a-comment-into-a-word-processing-document`。这份技能的判断、严重度和证据纪律仍按 SKILL.md 与审查报告契约执行。
