# 概要设计检查执行契约

本页把现有操作组织为可复用工序，不新增业务检查项，不扩展检查范围；概设内容只以 content-checklist.md 为准，判断与分级以 dimensions.md、report-contract.md 为准。

## 工序与数据

| 工序 | 输入 | 动作 | 产物及消费者 |
|---|---|---|---|
| 建立范围 | 用户任务、原稿、可选依据 | 区分整体/专题、阶段、现状/目标、版本和可读材料 | 审查上下文，供模型判断适用性；对有争议的基线向用户确认 |
| 读取定位 | 原稿 DOCX | word_comments.py index；实际查看审查范围内的图表 | paragraph-index.json，包含 source_sha256 与 paragraphs，供模型定位 |
| 语义检查 | 上下文、原文图表、内容清单 | 适用性→全局粒度→证据→失败路径→排除合理后移项→合并根因 | 模型形成发现与待确认项；需要结构化工作底稿时采用 report-contract.md |
| 形成批注 | 发现、原文索引 | 在对应段落写简明中文问题与建议 | comment-plan.json，供 word_comments.py apply/verify |
| 生成与核验 | 原稿、计划、新输出路径 | apply 并 verify；可用时打开/渲染检查 | 带批注副本，供用户/评审人员复核；交付说明列出问题数、待确认项数及未审范围 |

这些名称是建议的内部文件名，不要求向用户额外交付 JSON；运行工具时用实际参数指定。模板位于 assets 目录，复制后填入本次审查的真实信息，空数组不是“已经完成审查”的证据。

### 段落索引

`source_sha256` 绑定本轮原稿；`paragraphs[].paragraph` 从 1 开始且只对该原稿有效，`text` 是可定位正文，`drawings` 表示图/对象数量，`in_table` 说明是否在单元格。段落号不是页码。图片实际内容另用宿主图像工具核对，不根据图像数量判断设计是否完整或合理。

### 批注计划

`source_sha256` 原样取自索引；`annotations[]` 每项包含 `finding_id`、`paragraph`、`quote`、`text`。`quote` 必须是对应段的连续原文；图段可按原有规则为空。`text` 包含中文批注头，以及“问题、建议”两部分，工具自动添加编号与固定作者。同根因多处提醒复用 finding_id，不重复计数。完整格式见 word-comments.md。

### 结论

沿用现有四类状态：findings（发现问题）、clear（本次范围未发现问题且关键证据充分）、insufficient_evidence（证据不足）、out_of_scope（范围外）。有问题同时有缺证时用 findings 并保留待确认项。它们是文档检查结论，不能替换成生产验收或合规认证结论。

## 规则分三层

| 层级 | 可执行判据 | 产物/验证 |
|---|---|---|
| 脚本 | 原稿散列、段落/引用有效、输出不覆盖、批注作者与锚点、原有文档部件是否完整保留、底稿枚举与引文合法 | 内置工具校验结果、test_rules.py；能自动判定失败就整批报错 |
| 模型 | 本阶段适用性、结构/全局影响、同版本同条件比较、具体风险路径、图文含义、遗漏依据、重复根因、简明建议 | 可追踪发现及覆盖说明；程序校验通过不等于语义正确 |
| 问用户/权威负责人 | 冲突的权威基线、批准例外、缺少的专题或需求、影响关键结论的事实 | 可回答的确认项；尚未解决时保留证据不足的状态，并继续检查已有材料 |

## 接入条件

智能体须能读写用户授权目录、运行 Python 3.9+、理解中文材料；涉及图示判断时须能查看图片。没有图像读取或渲染器时明确区分“图未审”和“布局未核验”，不宣称已完成这些检查。工具的选择与调用方式由宿主平台决定。本技能不依赖固定名称的 MCP，数字员工 JSON 中的自主性级别也不构成额外操作授权。
